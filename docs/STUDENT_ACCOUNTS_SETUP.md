# Kidscade 학생 계정 1차 설정

이 버전은 **게스트 사용을 그대로 유지하면서**, 교사가 발급한 Kidscade ID + 6자리 PIN으로 학생이 로그인해 핵심 진행 상황을 D1에 저장하도록 합니다.

## 1. D1 마이그레이션 적용

Cloudflare D1의 `kidscade-stats` 데이터베이스에 `migrations/0002_student_accounts.sql`을 적용합니다.

Wrangler CLI를 쓰는 경우 예시는 다음과 같습니다.

```bash
npx wrangler d1 migrations apply kidscade-stats --remote
```

Cloudflare Dashboard의 D1 Console에서 SQL 파일 내용을 직접 실행해도 됩니다.

생성되는 테이블:

- `kidscade_classes`
- `student_accounts`
- `student_sessions`

## 2. Worker Secrets 두 개 등록

Cloudflare Worker의 Secrets에 아래 두 값을 등록합니다.

- `KIDSCADE_ADMIN_KEY`
  - 교사 관리 화면에 들어갈 때 사용하는 긴 관리 코드
  - 학생에게 공유하지 않습니다.
- `KIDSCADE_ACCOUNT_PEPPER`
  - 학생 PIN 해시에 사용하는 서버 전용 비밀값
  - 한 번 계정을 발급한 뒤에는 바꾸지 않는 것을 권장합니다. 이 값을 바꾸면 기존 PIN을 다시 발급해야 합니다.

둘 다 저장소나 프론트엔드 파일에 넣지 않습니다.

## 3. 교사 관리 화면

배포 후 다음 주소로 접속합니다.

```text
https://<Kidscade-domain>/teacher.html
```

교사 관리 코드(`KIDSCADE_ADMIN_KEY`)를 입력하면 다음을 할 수 있습니다.

- 학급 이름과 학생 수를 입력해 학생 계정 일괄 발급
- 자동 생성되는 `KC-XXXXX-01` 형태의 ID와 6자리 PIN 확인
- 로그인 카드 인쇄
- ID/PIN 목록 복사
- 학생별 닉네임, 마지막 로그인, 클라우드 저장 여부 확인
- PIN 초기화

PIN은 최초 발급 또는 초기화 직후에만 화면에 표시됩니다. 서버에는 PIN 원문이 저장되지 않고 HMAC-SHA256 해시만 저장됩니다.

## 4. 학생 로그인

Kidscade 메인 화면의 **내 프로필** 안에 `기록을 안전하게 보관하기`가 나타납니다.

학생은 교사가 준 ID와 PIN으로 로그인합니다. 새 계정의 첫 로그인이고 서버에 아직 저장된 진행 기록이 없다면, 그 브라우저에 있던 게스트 진행 상황을 자동으로 계정에 승계합니다.

1차 동기화 대상:

- 게스트 닉네임
- 씨앗
- 아바타 보유/장착 정보
- 개인 플레이 기록
- 상점 보유/장착 정보
- 쑥쑥랜드 펫 상태와 용품
- 정원 상태

게임별 독립 세이브(`벽란도 상행기`, `멜로디 공방`, `어항` 등)는 아직 계정 동기화 대상이 아닙니다. 이후 게임별 저장 API로 단계적으로 추가합니다.

## 5. 보안/운영 원칙

- 학생 이메일, 전화번호, 실명은 요구하지 않습니다.
- 로그인 세션은 `HttpOnly; Secure; SameSite=Strict` 쿠키로 30일 유지합니다.
- PIN 5회 연속 실패 시 해당 계정은 10분간 잠깁니다.
- 교사가 PIN을 초기화하면 기존 학생 세션도 함께 종료됩니다.
- 로그아웃 시 공용 기기에 남은 핵심 프로필 진행 정보는 삭제하고, 서버에는 마지막 동기화 상태가 남습니다.
- 교사 관리 코드는 `sessionStorage`에만 임시 보관되어 브라우저 탭을 닫으면 사라집니다.

## 6. 현재 범위와 다음 단계

이 버전은 **학생 계정 기반**입니다. 여러 교사가 각자 로그인하는 별도 교사 계정 시스템은 아직 만들지 않았습니다.

다음 확장 후보:

- 교사별 계정 및 담당 학급 권한
- 계정별 업적/레벨
- 게임별 최고기록 서버 저장
- 교사가 내는 주간 미션
- 반 랭킹/협동 목표
- 게임별 장기 세이브 동기화
