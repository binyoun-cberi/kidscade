# 키즈케이드 ChatGPT 프로젝트 지침 (복사용)

아래 **'복사할 지침'** 내용을 ChatGPT의 **게임 프로젝트 → 프로젝트 지침**에 직접 붙여 넣는다. 이 문서가 GitHub에 존재한다고 해서 ChatGPT 프로젝트 설정이 자동으로 바뀌지는 않는다.

## 복사할 지침

```text
키즈케이드(binyoun-cberi/kidscade) 관련 개발 요청에는 단일 일반 Chat에서 연속 개선 루프를 적용한다. 사용자가 단순 아이디어 토론만 요청한 경우 코드를 임의로 변경하지 않는다.

1. 매번 GitHub main의 최신 코드와 AGENTS.md, docs/CHAT_AGENT_WORKFLOW.md를 우선 확인한다. 기존 기능, Cloudflare Workers/D1/Durable Objects와 GitHub Actions→Wrangler 배포 흐름을 보존한다.
2. 대상 게임의 ID와 파일을 확인하고 docs/improvement-logs/<게임ID>.md가 있으면 이전 수정 내역, 실제 테스트, 남은 문제 및 다음 작업을 읽어 이어서 진행한다. 파일이 없으면 없는 것으로 기록하고 이전 테스트를 지어내지 않는다.
3. 분석·기획·구현·비평·검증 5가지 관점을 하나의 Chat에서 순차 적용한다. 서로 독립적인 AI 여러 개가 실행된다고 주장하지 않는다.
4. 코드를 바꿀 수 있는 요청은 분석→계획→비평→구현→검증→결과 분석을 기본 3회 이내에서 반복한다. 의미 없는 반복을 금지하고 한 요청에서 가능한 만큼 완료한다.
5. 실제로 실행한 명령·테스트·브라우저 플레이·결과만 검증 완료로 표시한다. 실행하지 못한 부분과 단순 추정은 분리한다. 가능하면 이전 버전과 수치 및 사용자 경험을 비교한다.
6. 작업 브랜치를 만들고 PR을 제출한다. main 직접 푸시, 자동 병합, 실제 배포, 원격 D1 마이그레이션, 유료 AI API, 비밀정보 접근은 별도 명시 승인 없이 하지 않는다.
7. 작업 종료 전에 게임별 개선 로그에 이번 요청, 적용한 변경, 각 반복의 실패/성공 근거, 테스트 결과, PR 링크, 다음 단계 및 제한 사항을 기록한다. 개인정보·키·토큰은 기록하지 않는다.
8. 불필요하게 사용자에게 '계속할까요?'라고 반복해서 묻지 말고 가능한 작업을 현재 응답에서 수행한다. 도구 접근·시간·사용량 한도로 중단되면 완료와 미완료를 정확히 구분한다.
9. 최종 보고는 변경 파일, 검증 결과, 남은 문제, PR/병합/배포 상태를 간결하고 분명히 정리한다.
이 규칙은 무제한·백그라운드 실행이나 ChatGPT 사용량 제한 해제를 뜻하지 않는다.
```

## 사용 예시

- `키즈케이드 핀볼 레이스를 개선해. 이전 개선 로그를 읽고 3회까지 수정·검증한 뒤 PR로 올려줘.`
- `못 찾겠다 꾀꼬리의 겹침 문제를 다시 봐. 이전 실패부터 이어서 진행해.`
- `운명의 주사위 기획만 토론해. 이번에는 코드를 바꾸지 마.`

## 주의

프로젝트 지침은 사용자가 ChatGPT 제품 UI에서 직접 저장해야 한다. GitHub의 `AGENTS.md`는 저장소 작업 규칙이고 ChatGPT 프로젝트 지침을 원격으로 바꾸는 설정 파일은 아니다.
