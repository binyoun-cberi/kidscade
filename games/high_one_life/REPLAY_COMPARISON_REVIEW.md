# 《단 하나의 인생》 다음 개선 루프 — 선택 기록과 두 삶 비교의 무결성

## 검수에서 확인된 실제 문제

`game.js`의 두 인생 비교는 이전·현재 선택 로그를 `new Map(choices.map(...[age,label]))`으로 축약했다. 같은 나이에 고려 피란·가족·생업 등의 선택을 여러 번 하면 같은 나이의 가장 마지막 기록만 남는다. 이후 비교 화면은 `World4.GATES` (16·20·29·42·64세)만 순회해, 실제 고려·조선 플레이에서 더 다양한 연령에 남긴 선택은 비교 자체에 나타나지 않았다.

한쪽 삶에서 해당 연령의 선택 기록이 없다는 이유만으로 '선택 이전에 삶을 마침'이라고 표시하는 문구도 실제 사망 기록과 관계없이 부정확한 판단이었다.

또한 `captureEnding`이 지원하는 시대별 선택 종류를 긴 배열로 하드코딩해 새 역사 선택 종류가 추가될 때 회고에서 누락될 가능성이 있었다.

## 변경

- 신규 `ending-choice-compare-v1.js`: 나이별 선택을 **배열**로 그룹화하며 해당 나이의 모든 선택을 로그 순서대로 유지한다.
- 이전/현재 삶에 등장한 **모든 연령의 합집합**을 나이순으로 비교한다. 변경 여부는 내용뿐 아니라 선택 개수와 순서까지 반영한다.
- `captureEnding`은 기존 `OneLifeBiography328.isChoice`를 재사용하여 `goryeo-choice`, `joseon341-choice`, 향후 `-choice` 또는 `:choice` 접미사의 기록을 포괄한다.
- 같은 나이에 여러 기록이 있는 경우 각각 번호를 붙이고, 양쪽 기록 개수를 표시한다.
- 기록 없음은 `그 나이에 기록된 선택 없음`으로 표현하여 사망 여부를 추정하지 않는다.
- 기존 생애 기록, 경제/체력/가족/출생·진행 확률, 저장 포맷은 변경하지 않는다.

## 검증과 한계

`tests/one-life-ending-compare-v1.test.cjs`에서 같은 나이의 중복 선택, 역사 특화 종류, 현대 기준 연령 외 기록, 기록 순서·개수 변화, 빈 저장 스냅샷, 잘못된 연령 값, 데이터 불변, 실제 `index.html`의 로드 순서, CI 스크립트 등록을 검사한다.

이는 **회고 비교의 정확성**을 높이는 작업이지 실제 게임의 재미나 픽셀 화풍을 AI 다수의 의견으로 검증한 결과가 아니다. 독립 모델 호출이나 GPU, 유료 API를 추가하지 않는다.

작업은 별도 브랜치·PR에서 이루어지며 사용자가 별도로 승인하지 않는 이상 병합하지 않는다.
