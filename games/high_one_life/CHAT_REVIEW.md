- 다른 게임, 저장 포맷, 역사 확률, 인물 상태 및 배포 설정 변경 없음.

## 역할별 1차 검수 (분석 → 기획 → 구현 → 비평 → 테스트)

### 발견 1: 고려 출생 추첨의 지역 고정
- 현재 고려 지방은 7곳인데 화면 추첨은 `(loops*7)%7`로 첫 지역만 표시.
- 실제 출생 지역은 기존 엔진의 선택으로 정해지므로, 게임 결과보다 **연출의 신뢰성**을 떨어뜨리는 문제.
- 추첨 폭과 서로소인 순환 간격을 선택하여 모든 지역을 한번씩 거친 뒤 반복하도록 수정.
- 출생 결과·인물 RNG와 저장 데이터는 절대 변경하지 않음.
- 2~15개 지역을 가진 예시와 실제 고려 7개 지역 모두에서 중복 없는 순환을 검증.

### 발견 2: 선택창을 다시 그릴 때 강제 스크롤
- `showDecision()`이 호출될 때마다 선택창의 `scrollIntoView()`가 실행되어,
  같은 선택을 이미 보고 있어도 페이지가 이동할 수 있음.
- 사건의 연도·나이·대기 중인 사건 ID가 바뀌었을 때만 선택창으로 이동하도록 개선.
- 역사 자료나 인물 기록을 탐색할 때 불필요한 강제 스크롤을 줄임.
- 선택지 내용과 게임 내 사건 결과를 변경하지 않음.

### 발견 3: 움직임 감소 설정 미반영
- 설정에서 애니메이션 감소를 요청해도 출생 룰렛은 19프레임 재생.
- 감소 설정이 활성화되면 출생 증명서와 실제 지역을 즉시 표시.
- 일반 이용자는 기존 추첨 시간을 유지.

### 발견 4: 선택 결과가 불분명한데도 무조건 붙는 추상적인 감상

- 이전 코드는 선택 후 수치 변화가 없어도 ‘그날의 일은 마음 한편에 남았다’
  또는 ‘당장은 눈에 띄는 변화가 없었다’라는 후일담을 추가로 기록.
- 실제 삶의 사건 결과는 각 선택 엔진이 이미 기록하므로, 확인되지 않은
  감상이나 단정으로 연대기를 채우지 않도록 수정.
- 능력치·생업·재산의 즉시 변화가 있는 경우에만 수치 변화 기록을 추가.
- 가족·사건·살림의 장기 변화를 거짓으로 '없음'이라 단정하지 않음.

## 검증 기준
- 코드 시뮬레이션: 모든 고려 지역을 표시하고 결과 선택을 바꾸지 않아야 함.
- 화면 내 재렌더: 같은 사건일 때 스크롤하지 않으며, 새 사건에 진입하면 이동해야 함.
- 움직임 감소: 추첨이 아닌 결과를 즉시 읽을 수 있어야 함.
- 수치 변화 없는 결정에 추상적인 후일담을 자동 생성하지 않아야 함.
- 각 선택 엔진의 실제 결정 기록은 유지되어야 함.
- 기존 `one-life` 시뮬레이션과 CI, 가능하면 브라우저 검증이 통과해야 함.
