# 《로타리클럽》 게임 기획 원본 및 개발 규약
최초 정리: 2026-10-25 · 게임 ID: `high_road_weaver` · 이전 명칭: `도시를 잇다`

> **기준 문서**: 새로운 기능 개발, 화면 개선, 난이도 조절, 에셋 교체, 성능 최적화 작업을 시작할 때마다 이 문서를 읽고, 변경 사항이 아래 원칙을 지키는지 확인한다. 이 문서와 실제 구현이 다르면 구현상 제한과 차후 작업을 함께 기록한다.

## 1. 한 문장
**도시는 스스로 성장하고, 플레이어는 한정된 자원으로 도로를 설계해 실제 자동차들의 교통체증을 해결한다.**
2D 탑다운 교통공학 퍼즐·도시 성장 시뮬레이션. 도로를 많이 짓는 것이 정답이 아니라 **병목을 줄이고 서로 다른 목적의 이동을 연결**하는 것이 목표.

## 2. 처음 제안된 핵심 요구(보존)
- 시작은 도시 두 개. 자동차가 실시간으로 도시 사이를 왕복한다.
- 출퇴근 집중 시간은 **시계·차량의 실제 움직임**으로 드러난다. 플레이어에게 교류 차량 수, 시간당 수요, 목적지별 발생량을 숫자로 노출하지 않는다.
- 마우스 드래그나 손가락 터치로 **도로를 자유롭게 그려 연결**한다. 직선, 곡선, 여러 갈래가 자연스럽게 형성된다.
- 건설 자재가 한정되어 있으며, 왕복 2·4·6차로 등 도로 폭을 선택한다.
- 교차로, 신호등, 로터리/회전교차로, 교통섬, 우회전 전용도로, 고가도로, 진출입로/램프 등 **작동 방식이 다른 도로 시설**을 배치한다.
- 일정 수준 이상 교통이 안정되면 새로운 기능의 도시가 추가된다. 무작위 재화 보상이 아닌 **혼잡을 이해하고 해결한 보상**이어야 한다.
- 도시 유형: 베드타운, 사무지구, 공업지구, 농업지구, 상업지구, 관광지구, 대형마트. 각각 통근·교대근무·화물·출하·쇼핑·주말 관광 등의 수요 시간대가 다르다.
- 교통체증은 미리 애니메이션으로 짠 연출이 아니다. **개별 차량·간격·차선·경로·합류/회전·신호에 따른 시뮬레이션 결과**여야 한다.
- 학생 대상이므로 초기 조작은 매우 단순해야 하지만, 깊게 플레이하면 입체 교차로 및 차선과 우회로를 연구할 수 있어야 한다.
- 모바일 터치/핀치 줌과 PC 마우스 모두 지원한다. 재미를 가리는 복잡한 HUD·개발자 문구·통계판은 피한다.

## 3. 지구별 교통 특성
| 유형 | 이동 패턴 | 유의할 도로 문제 |
|---|---|---|
| 베드타운 | 오전 출발 집중 / 저녁 귀가 집중 | 한쪽 방향만 막히는 통근로 |
| 사무지구 | 오전 유입 / 저녁 유출 | 진입로 집중, 좌회전 대기 |
| 공업지구 | 이른 오전 교대·오후 퇴근·물류 상시 | 가속 느린 트럭, 화물 우회로 |
| 농업지구 | 새벽 출하, 낮의 소규모 이동 | 느린 농기계, 화물 접속 |
| 상업지구 | 오후~저녁·주말 | 짧은 진출입, 상가 접근 |
| 관광지구 | 주말·휴일 한쪽 방향 쏠림 | 계절·요일별 혼잡 |
| 대형마트 | 저녁·주말 유입, 주차장 출차 집중 | 좌·우회전 충돌, 짧은 진입부 |

## 4. 핵심 플레이 루프
1. 지도에 나타난 도시·지역의 위치와 도로 자재를 살핀다.
2. 차선을 정하고 도로를 직접 그린다. 도로를 교차시키거나 우회로를 만든다.
3. 시계가 돌아가며 개별 차량이 실제 도로를 통과한다.
4. 출퇴근 시간과 구역별 활동을 관찰한다. 줄이 길어지는 곳을 본다.
5. 차선을 넓히거나 로터리·신호등·교통섬·고가도로·진출입로로 **정체 원인**을 해결한다.
6. 며칠간 흐름이 안정되면 새 지역이 나타나고 수요가 복잡해진다.
7. 실패해도 세이브를 잃지 않고 수정·되돌리기·재설계가 가능해야 한다.

## 5. 레벨 흐름
- **시작: 두 도시** (햇살마을 ↔ 중앙업무지구). 2~4차로, 곡선 연결. 단일 출퇴근 방향 병목.
- **초반: 공업지구**. 느린 트럭·교대 수요, 분기점·신호·로터리.
- **중반: 상업지구 및 대형마트**. 오후의 방문객 증가, 교통섬·우회전 전용 차로, 주차장 진입.
- **후반: 농업지구·관광지구**. 새벽 물류 및 주말 방문, 물·언덕 같은 장애물과 고가·램프.
- **장기: 광역도시**. 다중 도로망·입체 교차로·방향별 차로 최적화.
- 시간/해금/자재 수치는 **초기 조정값**이며 플레이 테스트로 균형을 맞춘다. 막연히 차량 수만 늘려 억지 실패를 만들지 않는다.

## 6. 도로 시설을 실제로 구현할 때의 의미
- **평면 교차로**: 도로가 같은 높이에서 만나는 노드. 교차로별 유입과 회전 충돌을 해결.
- **신호등**: 접근 방향/현시에 따라 진입을 제한. 막연히 정체가 사라지는 버프 금지.
- **회전교차로(로터리)**: **일방향 환상 차로**로 진입→회전→출구 주행. 중심부를 직선으로 관통할 수 없다. 진입 차량은 원형 구간 차량에게 양보.
- **교통섬**: 일부 회전 방향을 분리하는 실제 물리 경로. 건물/차선 장식만 추가하고 교통 성능을 자동으로 올리는 효과는 금지.
- **고가도로**: 지면 도로와 **고도가 다른 연결**. 서로 겹친다고 무조건 교차로가 생기면 안 된다.
- **램프/진출입로**: 지면 ↔ 고가도로의 명시적 진입 및 이탈 연결. 불가능한 높이로 순간이동 금지.
- **우회도로/일방통행**: 실제 이동 가능한 방향/경로에 적용.
- **가변차로**: 시간에 따라 이동 허용 방향이 변경되되 기존 차량의 안전한 해제가 필요(후순위).

## 7. 화면과 조작
- 가로형·세로형 PC/스마트폰에서 읽히는 2D 탑다운. 도시 구역과 도로가 핵심, 시계·남은 자재·건설 도구는 간결하게.
- 클릭·탭 두 번으로 직선 연결; 드래그로 곡선 연결; 두 손가락으로 지도를 확대·축소.
- 도구 선택 → 지도 조작 → 미리보기와 건설 비용 → 도로 완성의 직관적인 순서.
- 고가도로·램프·로터리는 **선택한 도구와 실제 동작이 일치해야** 한다. 배경 그림만 변하는 가짜 도구 금지.
- 텍스트 피드백은 '도로가 이어졌어요', '출근길에 차가 몰려요'처럼 자연스러운 한국어 사용.
- 수치 데이터는 내부 시뮬레이션에만 유지. 화면에는 시간 강조, 줄 선 자동차, 신호 변화, 서행/원활 등을 표시.

## 9. 아키텍처·일관성
- 경로 및 게임 ID: `games/high_road_weaver/`, `high_road_weaver`. **사용자 저장·게임 통계 호환을 위해 이름이 바뀌어도 ID와 저장 키는 유지한다.**
- 엔진(`sim-core.mjs`)은 DOM에 의존하지 않고 도로·차로·고도별 그래프와 차량 이동을 유지한다.
- 렌더러(`game.js`)는 Canvas 2D에서 도로 편집, 카메라 및 화면만 담당한다.
- 데이터는 옛 저장 버전과 호환되게 확장한다. 잘못된 데이터는 안내 후 안전하게 처리한다.
- 지도 내 도로망 수정 시 차량이 사라지거나 텔레포트하지 않아야 한다. 기존 주행 경로 마무리 처리 우선.
- 게임 시작, 정지, 팝업, 탭 이동 시 자동 저장/일시정지 동작 점검.
- 동일한 도로 조각/연결점에서 간헐적 길 찾기 실패가 반복되지 않도록 그래프 연결성 테스트 유지.

## 12. 2026-10-25 진행 기록 — 《로타리클럽》 v2 교통 구조
- 실제 구현: 회전교차로는 기존 지상 교차로 내부의 직진 구간을 제거하고, 외곽에 단방향 환상 차로를 연결. 환상 구간에서 나오는 경로에 따라서만 주행하며 입구에는 양보 조건 적용.
- 교통섬: 기존 교차로 중 사용자가 선택한 모퉁이에 단방향 우회전 연결도로 설치. 도로 그래프가 실질적으로 분기함.
- 고가도로: 층별 노드(`@0`/`@1`)와 별도 접속 구조. 지상 교차 시 연결 없음.
- 진출입로: 지상↔고가를 연결하는 램프를 별도 경로로 분할, 등·하행 양방향 허용.
- 검수: 엔진 격리 실행으로 회전교차로 방향성·주행·교통섬 경로·교차 고도 분리·램프 등하행·구 버전 저장 복원 등을 확인. **실제 브라우저/모바일 화면 검증은 별도**.
- 다음 목표: 엔진의 진로 선택·차로변경과 교통량 과밀에서의 양보 정체 처리, 도시 5–7종 추가, UI 방향 미리보기/실제 이미지 에셋 검수.

## 18. 2026-10-25 — 회전교차로 장시간 시뮬레이션과 개선

### 문제 재현
- PR #703의 교통 엔진으로 7개 지역·주말 5시간(0.1초씩 1,500회, 하루 120초 규칙)을 반복 시뮬레이션했다. 동일한 4차로 중앙 허브는 목적지 도착 **302대**·출발 대기 **436대**, 기존 2차로 회전교차로 추가 시 목적지 도착 **170대**·출발 대기 **567대**였다. 합류하는 길이 많아도 고정 2차로 순환로 하나로 주행시켜 지나치게 정체됨.

### 적용 내용
- 진입 갈래가 **5개 이상**인 회전교차로는 **4차로**로 건설하고, 공사비를 75에서 95로 책정. 일반 4방향 이하 교차로는 기존 **2차로·75 자재**를 유지.
- 순환로 차량이 진입로 직전에 있을 때 양보하는 거리의 일부 과도한 보수성을 줄였다. 다음 도로 같은 차로의 차량과 기본 안전간격을 지키는 규칙은 유지.
- 넓은 회전교차로의 중앙 녹지와 한국어 안내를 폭에 맞게 표현한다. 넓게 바꿔도 항상 효율적인 것은 아니므로, 심한 교통 상황에서는 우회도로가 도움 될 수 있다고 안내한다.
- 저장 데이터 v3의 회전교차로 객체에 차선 수를 저장. 기존 v1/v2 저장에서 차선 수가 없는 회전교차로는 이전처럼 2차로로 복원한다.

### 재검증
- 같은 조건의 주말 5시간 반복 실험에서 넓힌 회전교차로 도착 **249대**, 대기 **488대**. 기존 170대/567대에 비해 개선. 하지만 일반 허브(302대/436대)보다 여전히 성능이 낮다. **회전교차로가 고밀도 허브의 만능 해결책이라는 잘못된 메시지를 전달하지 말 것.**
- 54개 엔진·모의 UI 검사 격리 JavaScript 환경 통과(이전 51개 + 신규 3개). 신규 검사는 5개 이상 진입 도로 시 폭·비용·저장, 4방향 교차로의 기존 규칙과 구형 저장, 주말 고밀도 도착량.
- 남은 과제: 환상도로 구간이 지나치게 잘게 나뉠 때의 차량 간격/진입 제어, 불필요하게 긴 한 방향 우회, 우회전 전용 분리와 로터리의 분업, 물리적 충돌과 정교한 차선 예약, 실기기 프레임 성능 및 재미 확인.

## 19. 2026-10-25 — 환상 차로 연속 간격과 화면 품질 점검

### 교통 엔진 실제 재검수
- **원인**: 회전교차로의 도로 그래프는 약 1~30px 길이의 짧은 구간으로 나뉘어 있다. 기존에는 현재 도로 조각에서만 앞차 간격을 검사하고, 다음 조각에 차가 있으면 입구를 막는 규칙을 사용했다. 그 결과 같은 원의 이웃한 조각에 있는 차끼리 실제 좌표가 가까워져 겹칠 수 있었다.
- **수정**: 모든 순환 도로 조각을 하나의 원형 주행 경로로 해석해, **같은 차선의 앞차까지 실제 원호 거리**를 계산한다. 일반도로에서 들어올 때는 환상로 앞차뿐 아니라 뒤따르는 순환 차에게도 양보한다. 출구가 2차로로 좁아지는 경우 순환 구간이 매우 짧아 차선 변경을 못 하는 차량은 출구 진입 안전 간격을 확인한 뒤 적절한 차로로 합류한다.
- **동작과 연출**: 회전교차로를 여러 조각으로 나눠도 자동차의 방향은 원 중심에 대한 접선으로 부드럽게 계산한다. 진입 갈래가 많은 4차로형 회전교차로는 반지름을 37에서 50으로 넓혀 실제 차간 간격을 확보한다. 큰 회전교차로 중앙 녹지도 새로운 폭에 맞게 표현한다. 기존에 지어진 회전교차로의 저장값은 변경하지 않는다.
- **비교**: 이전 PR #703의 동일 교통 엔진을 기준으로 7개 지역·토요일 오전부터 120초(0.1초 × 1,200회) 실행. 같은 차선 회전교차로 차량의 중심점 간 거리 **13px 미만 근접 표본**이 기존 **388회 → 새 버전 18회**로 감소(매 4틱 검사). 같은 기간 도착 차량 **183 → 182대**, 대기 **456 → 457대**로 거의 동일. 이는 차량 이미지 충돌을 직접 판정한 수치는 아니고 반복 관측된 근접 대리 지표다.
- **검증**: 순환 도로 경계 근접, 좁은 출구 차선 안전 합류, 잘게 나뉜 링의 이미지 방향 연속성 등 회귀 검사 추가.

### 화면 배치·사용성 점검
- 실제 클라우드 배포 페이지 접근은 불가능했으므로, 저장소의 **HTML 문구와 주요 CSS를 사용한 로컬 레이아웃 재현본**을 Chromium에서 1365×768(PC), 390×844 및 360×780(휴대전화) 크기로 렌더링하고 스크린샷을 관찰했다. 지도 배경/자동차는 원본 게임 Canvas를 실행한 것이 아니라 이를 모사한 시각 보조 장면이다. **실제 게임 브라우저 플레이 검수라고 기록하지 않는다.**
- **문제**: 휴대전화 하단 8개 도구가 한 줄로 길게 배치되어 차로 선택·되돌리기가 화면 밖에 있었고, 도구 줄을 밀어야 한다는 안내도 약했다. 360px 화면에서는 상단 정보가 좁게 눌려 보였다. 전체 지도 배율에서는 작은 차량/지역 이름도 읽기 어려울 수 있었다.
- **개선**: 휴대전화 하단 메뉴를 가로 스크롤 도구 행 + **항상 보이는 2·4·6차로 및 되돌리기 행**으로 분리하고 가로 스크롤 표시를 둔다. 모바일 HUD는 시간·자재·교통 흐름을 정돈한다. 600px 이하의 전체 지도에서는 차량 스프라이트 및 도시 라벨을 적정 비율로 확대하되 PC 기본 화면에는 적용하지 않는다. 실제 주행속도가 낮은 차량 위치에만 옅은 따뜻한 색의 혼잡 표시를 그려 막힌 곳을 알아차리도록 했다. 학생에게 차량 수·통행량 숫자를 직접 보여주지는 않는다.
- **검사**: 기존 엔진·모의 UI 검사를 모두 포함한 총 **59개** 격리 JavaScript 회귀 검사 통과. 정규 CI 명단에 기존 테스트 경로를 유지. 모바일 CSS 구조 검사와 가짜 Canvas의 정체 표시 검사 추가. GitHub Actions 최종 결과·실제 Safari/Chrome 렌더링·실제 학생 플레이는 별도로 검증해야 한다.
- **한계**: 아직 실제 차량 사각형의 회전 충돌 다각형 판정, 복잡한 교차로 전체 차선 예약, 휴대전화 실기기 저성능 FPS는 해결하지 않았다. 기존 데이터 호환, 게임 ID/저장 키, 자산 라이선스 및 비용 정책은 그대로 보존한다.
