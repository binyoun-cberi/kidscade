# 《로타리클럽》 게임 기획 원본 및 개발 규약
최초 정리: 2026-10-25 · 게임 ID: `high_road_weaver` · 이전 명칭: `도시를 잇다`

> **기준 문서**: 새로운 기능 개발, 화면 개선, 난이도 조절, 에셋 교체, 성능 최적화 작업을 시작할 때마다 이 문서를 읽고, 변경 사항이 아래 원칙을 지키는지 확인한다. 이 문서와 실제 구현이 다르면 구현상 제한과 차후 작업을 함께 기록한다.

## 1. 한 문장
**도시는 스스로 성장하고, 플레이어는 한정된 자원으로 도로를 설계해 실제 자동차들의 교통체증을 해결한다.**
2D 탑다운 교통공학 퍼즐·도시 성장 시뮬레이션. 도로를 많이 짓는 것이 정답이 아니라 **병목을 줄이고 서로 다른 목적의 이동을 연결**하는 것이 목표.

## 2. 처음 제안된 핵심 요구(보존)
- 시작은 도시 두 개. 자동차가 실시간으로 도시 사이를 왕복한다.
- 출퇴근 집중 시간은 **시계·차량의 실제 움직임**으로 드러난다. 플레이어에게 교류 차량 수, 시간당 수요, 목적지별 발생량을 숫자로 노출하지 않는다.
- 마우스 드래그나 손가락 터치로 **도로를 자유롭게 그려 연결**한다. 직선, 곡선, 여러 갈래가 자연스럽게 형성된다.
- 건설 자재가 한정되어 있으며, 왕복 2·4·6차로 등 도로 폭을 선택한다.
- 교차로, 신호등, 로터리/회전교차로, 교통섬, 우회전 전용도로, 고가도로, 진출입로/램프 등 **작동 방식이 다른 도로 시설**을 배치한다.
- 일정 수준 이상 교통이 안정되면 새로운 기능의 도시가 추가된다. 무작위 재화 보상이 아닌 **혼잡을 이해하고 해결한 보상**이어야 한다.
- 도시 유형: 베드타운, 사무지구, 공업지구, 농업지구, 상업지구, 관광지구, 대형마트. 각각 통근·교대근무·화물·출하·쇼핑·주말 관광 등의 수요 시간대가 다르다.
- 교통체증은 미리 애니메이션으로 짠 연출이 아니다. **개별 차량·간격·차선·경로·합류/회전·신호에 따른 시뮬레이션 결과**여야 한다.
- 학생 대상이므로 초기 조작은 매우 단순해야 하지만, 깊게 플레이하면 입체 교차로 및 차선과 우회로를 연구할 수 있어야 한다.
- 모바일 터치/핀치 줌과 PC 마우스 모두 지원한다. 재미를 가리는 복잡한 HUD·개발자 문구·통계판은 피한다.

## 3. 지구별 교통 특성
| 유형 | 이동 패턴 | 유의할 도로 문제 |
|---|---|---|
| 베드타운 | 오전 출발 집중 / 저녁 귀가 집중 | 한쪽 방향만 막히는 통근로 |
| 사무지구 | 오전 유입 / 저녁 유출 | 진입로 집중, 좌회전 대기 |
| 공업지구 | 이른 오전 교대·오후 퇴근·물류 상시 | 가속 느린 트럭, 화물 우회로 |
| 농업지구 | 새벽 출하, 낮의 소규모 이동 | 느린 농기계, 화물 접속 |
| 상업지구 | 오후~저녁·주말 | 짧은 진출입, 상가 접근 |
| 관광지구 | 주말·휴일 한쪽 방향 쏠림 | 계절·요일별 혼잡 |
| 대형마트 | 저녁·주말 유입, 주차장 출차 집중 | 좌·우회전 충돌, 짧은 진입부 |

## 4. 핵심 플레이 루프
1. 지도에 나타난 도시·지역의 위치와 도로 자재를 살핀다.
2. 차선을 정하고 도로를 직접 그린다. 도로를 교차시키거나 우회로를 만든다.
3. 시계가 돌아가며 개별 차량이 실제 도로를 통과한다.
4. 출퇴근 시간과 구역별 활동을 관찰한다. 줄이 길어지는 곳을 본다.
5. 차선을 넓히거나 로터리·신호등·교통섬·고가도로·진출입로로 **정체 원인**을 해결한다.
6. 며칠간 흐름이 안정되면 새 지역이 나타나고 수요가 복잡해진다.
7. 실패해도 세이브를 잃지 않고 수정·되돌리기·재설계가 가능해야 한다.

## 5. 레벨 흐름
- **시작: 두 도시** (햇살마을 ↔ 중앙업무지구). 2~4차로, 곡선 연결. 단일 출퇴근 방향 병목.
- **초반: 공업지구**. 느린 트럭·교대 수요, 분기점·신호·로터리.
- **중반: 상업지구 및 대형마트**. 오후의 방문객 증가, 교통섬·우회전 전용 차로, 주차장 진입.
- **후반: 농업지구·관광지구**. 새벽 물류 및 주말 방문, 물·언덕 같은 장애물과 고가·램프.
- **장기: 광역도시**. 다중 도로망·입체 교차로·방향별 차로 최적화.
- 시간/해금/자재 수치는 **초기 조정값**이며 플레이 테스트로 균형을 맞춘다. 막연히 차량 수만 늘려 억지 실패를 만들지 않는다.

## 6. 도로 시설을 실제로 구현할 때의 의미
- **평면 교차로**: 도로가 같은 높이에서 만나는 노드. 교차로별 유입과 회전 충돌을 해결.
- **신호등**: 접근 방향/현시에 따라 진입을 제한. 막연히 정체가 사라지는 버프 금지.
- **회전교차로(로터리)**: **일방향 환상 차로**로 진입→회전→출구 주행. 중심부를 직선으로 관통할 수 없다. 진입 차량은 원형 구간 차량에게 양보.
- **교통섬**: 일부 회전 방향을 분리하는 실제 물리 경로. 건물/차선 장식만 추가하고 교통 성능을 자동으로 올리는 효과는 금지.
- **고가도로**: 지면 도로와 **고도가 다른 연결**. 서로 겹친다고 무조건 교차로가 생기면 안 된다.
- **램프/진출입로**: 지면 ↔ 고가도로의 명시적 진입 및 이탈 연결. 불가능한 높이로 순간이동 금지.
- **우회도로/일방통행**: 실제 이동 가능한 방향/경로에 적용.
- **가변차로**: 시간에 따라 이동 허용 방향이 변경되되 기존 차량의 안전한 해제가 필요(후순위).

## 7. 화면과 조작
- 가로형·세로형 PC/스마트폰에서 읽히는 2D 탑다운. 도시 구역과 도로가 핵심, 시계·남은 자재·건설 도구는 간결하게.
- 클릭·탭 두 번으로 직선 연결; 드래그로 곡선 연결; 두 손가락으로 지도를 확대·축소.
- 도구 선택 → 지도 조작 → 미리보기와 건설 비용 → 도로 완성의 직관적인 순서.
- 고가도로·램프·로터리는 **선택한 도구와 실제 동작이 일치해야** 한다. 배경 그림만 변하는 가짜 도구 금지.
- 텍스트 피드백은 '도로가 이어졌어요', '출근길에 차가 몰려요'처럼 자연스러운 한국어 사용.
- 수치 데이터는 내부 시뮬레이션에만 유지. 화면에는 시간 강조, 줄 선 자동차, 신호 변화, 서행/원활 등을 표시.

## 9. 아키텍처·일관성
- 경로 및 게임 ID: `games/high_road_weaver/`, `high_road_weaver`. **사용자 저장·게임 통계 호환을 위해 이름이 바뀌어도 ID와 저장 키는 유지한다.**
- 엔진(`sim-core.mjs`)은 DOM에 의존하지 않고 도로·차로·고도별 그래프와 차량 이동을 유지한다.
- 렌더러(`game.js`)는 Canvas 2D에서 도로 편집, 카메라 및 화면만 담당한다.
- 데이터는 옛 저장 버전과 호환되게 확장한다. 잘못된 데이터는 안내 후 안전하게 처리한다.
- 지도 내 도로망 수정 시 차량이 사라지거나 텔레포트하지 않아야 한다. 기존 주행 경로 마무리 처리 우선.
- 게임 시작, 정지, 팝업, 탭 이동 시 자동 저장/일시정지 동작 점검.
- 동일한 도로 조각/연결점에서 간헐적 길 찾기 실패가 반복되지 않도록 그래프 연결성 테스트 유지.
